# kicadmium agent notes

Single-binary Rust workbench, same shape as
https://github.com/meawoppl/single-binary-rust-website:

- `shared/` — serde API/event types used by both sides.
- `backend/` — axum server + CLI as the `backend` library; `src/main.rs` is a
  thin `kicadmium` binary that embeds `frontend/dist` (asset table generated by
  `build.rs`, served by `frontend_assets.rs`). The asset list is fixed at
  compile time, so restart the server after a frontend rebuild. Keep logic out
  of `main.rs`: sccache never caches `bin` crates, and the install script
  (`scripts/setup.sh`) relies on the library being cacheable.
- `frontend/` — Yew (trunk) workbench. `frontend/static/kicad-viewer/` holds the
  vendored third-party viewer runtimes (ecad-viewer, three.js, occt), copied to
  `dist/kicad-viewer/` by trunk. Gerbers use pastebom's `eda-view` crate
  (`gerber_view` module) directly from Rust; the 2D canvas, search and
  Schematic view come from its `components` module. Release builds use the
  `wasm-release` cargo profile (fat LTO, selected in `index.html`) to keep the
  bundle size flat.
- Schematic and library-symbol scenes come from `eda_view::schematic` (backend
  only). `eda-view` is the single pastebom dependency, one crates.io version in
  the workspace `Cargo.toml`; each crate enables only the features
  it uses (backend `schematic`, frontend `yew` + `gerber-view`). Never enable
  `kicad`, `strokes` or `schematic` for the frontend: check with
  `cargo tree -p frontend --target wasm32-unknown-unknown -e features`.

`backend/build.rs` runs `trunk build` (own target dir, `target/frontend`) whenever
`frontend/dist` is missing or older than frontend/shared sources, so
`cargo build -p backend` is the whole build. Needs `trunk` on PATH;
`KICADMIUM_SKIP_FRONTEND_BUILD=1` embeds whatever dist exists. For UI work,
`cd frontend && trunk watch` alongside `cargo run -p backend -- serve`.

## Rules

- All first-party code is Rust. Vendored JS/WASM viewer runtimes stay vendored;
  do not hand-edit them except to refresh from upstream.
- kicadmium never downloads or bundles KiCad. It discovers `kicad-cli`
  (`KICADMIUM_KICAD_CLI`, `KICAD_CLI`, `PATH`, stock install paths).
- `kct/` is a native Rust port of rjwalters/kicad-tools, run as
  `kicadmium kct -- <command>`. No Python anywhere; see `kct/PORTING.md`.
- Mutating `kct` commands are design edits: clean tree or explicit branch only.
- Before pushing: `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo test --workspace`.
